## Unreal Engine (applies ONLY to Unreal work: a *.uproject in the working directory, a parent, or a subfolder up to 3 levels down)

- `<Engine>` below = the Unreal install matching the project's `EngineAssociation` (e.g. `C:\Program Files\Epic Games\UE_5.8`).
- The Unreal Editor MCP server is configured globally in Claude Code as `unreal-mcp` (user scope): a stdio bridge (`%USERPROFILE%\.ue-ai-editor-stack\unreal_mcp_bridge.py`, run by the engine's Python) to the editor's server at http://127.0.0.1:{{PORT}}/mcp. Projects do NOT need their own `.mcp.json` - ignore hints to run `ModelContextProtocol.GenerateClientConfig`.
- The bridge stays connected whether or not an editor runs and lists the editor's tools from its last known list, but calls only work while the project is open in Unreal Editor. A call that returns "Unreal Editor is not reachable" means no editor answers: ask the user to open the project, then call again - no `/mcp` needed. The server auto-starts with the editor (global setting in `%LOCALAPPDATA%\Unreal Engine\Engine\Config\UserEditorPerProjectUserSettings.ini`), and the `AIEditorStack` plugin starts it itself a few seconds after launch if it is not running. Only one editor at a time can own the port; a second editor waits and takes the port over when the first one closes (log line `AI Editor Stack: port {{PORT}} is held by PID ...`). `{{REPO_DIR}}\tools\mcp_check.ps1` shows which process holds the port and how Claude Code is wired.
- If the `unreal-mcp` tools are missing from the session (`/mcp` shows it failed - an old direct HTTP registration), stop and ask the user to reconnect it in `/mcp` (re-running `install.ps1 -SkipVibeUE` switches it to the bridge). Never drive the editor around it by posting to the HTTP endpoint from the shell.
- Claude desktop app on Windows is an MSIX package: new files that its shell (or an editor started from that shell) writes under `%LOCALAPPDATA%` / `%APPDATA%` are redirected to `%LOCALAPPDATA%\Packages\Claude_*\LocalCache` and are invisible to the editor the user starts. Create files the editor must read from the editor's Python (`execute_python_code`) or outside AppData, check them from the editor's Python, and don't launch Unreal Editor from the shell unless the user asks.
- Epic's Unreal MCP, the engine AI toolsets and VibeUE are enabled for every project by the engine plugin `AIEditorStack` (`<Engine>\Engine\Plugins\Marketplace\AIEditorStack`). Do not add these plugins to `.uproject` files. Source and installer: `{{REPO_DIR}}` (https://github.com/metraveer/ue-ai-editor-stack).
- Before the first editor action in a session, read the VibeUE agent guide: `<Engine>\Engine\Plugins\Marketplace\VibeUE\Content\samples\AGENTS.md.sample` (execute_python_code batching, discover_python_class, ListSkills/GetSkills, capture_image) and the stack's notes `<Engine>\Engine\Plugins\Marketplace\AIEditorStack\Docs\AGENT_NOTES.md` (known traps: virtual-texture export breaking Python, decal sort order, VT sampler types, Niagara template loop settings, stale nDisplay screen previews in captures; helpers in `ai_editor_stack.ue_helpers`).
- `GameFeaturesToolset` and `ConversationToolset` are intentionally NOT enabled engine-wide. If the current project uses the `GameFeatures` plugin (Lyra-style modular features, `Plugins/GameFeatures/`) or the `CommonConversation` plugin (NPC dialogue graphs), tell the user once and offer to add the matching toolset to that project's `.uproject` (editor-only, `"TargetAllowList": ["Editor"]`).
- Fab assets (VibeUE `FabService`, skill `fab`): importing from the user's owned Fab library works through their Epic login. The public free-catalog search uses unofficial fab.com endpoints and can fail with HTTP 403 in some networks/regions; then ask the user to add the free asset to their Fab library in the browser and import it from the library. Never accept a license/EULA on the user's behalf.
- Sketchfab models: toolset `SketchfabTools` (reach it through `describe_toolset` / `call_tool`). Flow: `search` -> show the user name, author, license, face count, GLB size and the sketchfab.com link -> `import_model`. Search hides NonCommercial/NoDerivs/Editorial licenses by default; never pass `allow_restricted_license=true` without the user's explicit OK. Credits go to `<Project>/Credits/Sketchfab.md` automatically - remind the user that CC BY licenses require crediting the author. If no token is configured (a tool reports it, or `get_account` fails): call `open_token_dialog` - it opens a window on the user's desktop and returns at once - ask the user to paste their token into that window (https://sketchfab.com/settings/password -> API Token), wait for their reply, then call `get_account` to confirm. Never ask the user to send or paste the token into the chat; if they do anyway, don't repeat it and suggest regenerating it on Sketchfab. The same window is in the editor under Tools > AI Editor Stack > Sketchfab token… and via `{{REPO_DIR}}\tools\set_sketchfab_token.ps1`. The token lives in `%USERPROFILE%\.ue-ai-editor-stack\sketchfab_token.txt` (older copies in AppData are picked up and moved automatically) - never read or print it. If `import_model` returns `warnings` (deleted empty meshes, unlit materials), pass them on to the user.
- Never read or edit `.uasset`/`.umap` files from disk - always go through the MCP tools / `unreal` Python API.
- `execute_python_code` saves changed packages by default (`auto_save=true`); pass `auto_save=false` for experiments. Before large or bulk edits, remind the user to save and back up the project; group multi-step edits with VibeUE `TransactionService` so they undo as one step.
- When the user installs a new Unreal Engine version (or wants to update VibeUE): with the editor closed, run `powershell -ExecutionPolicy Bypass -File "{{REPO_DIR}}\install.ps1" -EngineDir "<new Engine>"`. If new Epic toolsets appear, add them to `AIEditorStack\AIEditorStack.uplugin` in the repo.
